# Text size (Dynamic Type) limits: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Text follows the phone's text-size setting up to a limit instead of without one: × 1.16 in the editor, × 1.35 on every other screen, × 1.65 for nine paragraphs on scrolling pages, and never for content drawn in the video frame or on the timeline. At the default text size nothing changes by one pixel; at larger sizes nothing is clipped, overlaps, or moves the preview or the timeline; at the accessibility sizes a touch-and-hold on a capped control shows its name large.

**Architecture:** `src/ui/Text.tsx` becomes the only file that renders React Native's `Text` / `TextInput`, as `KitText` and `KitInput`. `KitText` picks its cap from the tone (`useTone()`: `editor` → `theme.textScale.editor`, a screen → `.screen`), or from its `scale` prop (`"reading"`, `"fixed"`). A text that is limited to lines (`numberOfLines`, or the new `fit`) also "fits back" while it is shown larger than the default: `adjustsFontSizeToFit` with `minimumFontScale = (its own ?? 1) / shown scale`, so it never needs more width than it has today. The phone's text size is read in ONE file (`src/ui/phoneTextSize.ts`), which `jest.setup.ts` replaces with a test phone at the default size (the Jest preset's own phone says `fontScale: 2`). Capped controls spread `largeContent(title)` — iOS's large-content viewer. No layout number changes anywhere.

**Tech Stack:** Expo SDK 57, React Native 0.86.3, React 19.2, TypeScript strict, Jest (`jest-expo`) + RNTL 14. **No new package, no Swift, no native build, no `app.json` change.**

**Spec:** `docs/superpowers/specs/2026-10-12-text-size-design.md` (binding: §3 D1–D10, §4 the API, §5 the kit table, §6 the heights table, §8 the phone checklist, §9 the unverified list).

type Json = { type: string; props: Record<string, unknown>; children: (Json | string)[] | null };
const NOT_PIXELS = new Set(["maxFontSizeMultiplier", "allowFontScaling", "accessibilityShowsLargeContentViewer", "accessibilityLargeContentTitle"]);

function bare(node: Json | string | null): unknown {
  if (node === null || typeof node === "string") return node;
  const props: Record<string, unknown> = {};
  for (const key of Object.keys(node.props).sort()) {
    const value = node.props[key];
    if (NOT_PIXELS.has(key) || typeof value === "function" || value === undefined) continue;
    props[key] = value;
  }
  return { type: node.type, props, children: (node.children ?? []).map(bare) };
}

```ts
import { Dimensions } from "react-native";

/**
 * The phone's text size (Settings → Display & Brightness → Text Size, and Accessibility → Larger Text) as React Native's font scale:
 * 1 at the default, 1.353 at the largest standard size, 3.571 at the largest accessibility size. THE only file that asks
 * (textScale.guard.test.ts). Under Jest the setup file stands in for it: the preset's own phone says 2.
 */
export function readFontScale(): number {
  const scale = Dimensions.get("window").fontScale;
  return Number.isFinite(scale) && scale > 0 ? scale : 1;
}
/** Tells `listener` whenever the window's numbers change (iOS sends them again when the text size does). Returns the remover. */
export function onFontScale(listener: () => void): () => void {
  const subscription = Dimensions.addEventListener("change", listener);
  return () => subscription.remove();
}
```

```ts
import { act, screen } from "@testing-library/react-native";

type TestPhone = { __setFontScale: (scale: number) => void };
/**
 * Tests only: the user moves the phone's text-size slider while the app is open. 1 = the default; 1.353 = the largest standard size;
 * 3.571 = the largest accessibility size. The size outlives the test: end a suite that uses it with `afterEach(() => textSize(1))`.
 */
export async function textSize(scale: number): Promise<void> {
  await act(async () => { (jest.requireMock("@/src/ui/phoneTextSize") as TestPhone).__setFontScale(scale); });
}

type Json = { type: string; props: Record<string, unknown>; children: (Json | string)[] | null };
export type TextNode = { type: string; props: Record<string, unknown>; text: string };
const words = (node: Json | string): string => (typeof node === "string" ? node : (node.children ?? []).map(words).join(""));

/** Every text and text field on screen as the phone is given it (host `Text` / `TextInput`), nested spans and icon glyphs included. */
export function texts(): TextNode[] {
  const found: TextNode[] = [];
  const walk = (node: Json | string | null) => {
    if (!node || typeof node === "string") return;
    if (/Text/.test(node.type)) found.push({ type: node.type, props: node.props, text: words(node) });
    for (const child of node.children ?? []) walk(child);
  };
  const tree = screen.toJSON() as unknown as Json | Json[] | null;
  for (const top of Array.isArray(tree) ? tree : [tree]) walk(top);
  return found;
}

/** The texts that would follow the phone without a limit: neither a cap of 1 or more nor `allowFontScaling={false}`. Empty on anything built from the kit. */
export function unruled(): string[] {
  return texts().filter((t) => t.props.allowFontScaling !== false && !(typeof t.props.maxFontSizeMultiplier === "number" && t.props.maxFontSizeMultiplier >= 1))
    .map((t) => `${t.type} "${t.text}"`);
}
```

import { useSyncExternalStore } from "react";
import { theme, type Tone } from "@/src/theme/theme";
import { onFontScale, readFontScale } from "./phoneTextSize";
import { useTone } from "./tone";

/**
 * How a text follows the phone's text size. `chrome` (the default): up to the cap of the family it is drawn in — the editor's, or a
 * screen's. `reading`: a paragraph under a title on a page that scrolls; further, on a screen only. `fixed`: never — content drawn in
 * the video frame, marks on the timeline, a glyph used as a picture (the exact list is pinned in textScale.guard.test.ts).
 */
export type TextRole = "chrome" | "reading" | "fixed";

/** The largest multiplier a text of this role reaches in this family. In the editor the family wins: a reading text is capped like the rest. */
export const textCap = (tone: Tone, role: TextRole): number =>
  role === "fixed" ? 1 : tone === "editor" ? theme.textScale.editor : role === "reading" ? theme.textScale.reading : theme.textScale.screen;

/** The scale a text is really shown at: what the phone asks for, held at the cap. Below the default it is the phone's own. */
export const shownScale = (phone: number, cap: number): number => Math.min(phone, cap);

/** The phone's text size now, kept up to date. Only a part that must know it calls this (a line-limited text): it is drawn again when the size changes. */
export const usePhoneScale = (): number => useSyncExternalStore(onFontScale, readFontScale, readFontScale);

/** The scale a text of this role is shown at here (1 for a fixed one): for a layout that must know. Nothing in the app needs it yet. */
export function useTextScale(role: TextRole = "chrome"): number {
  const tone = useTone();
  const phone = usePhoneScale();
  return role === "fixed" ? 1 : shownScale(phone, textCap(tone, role));
}

export type Fit = { numberOfLines?: number; adjustsFontSizeToFit?: boolean; minimumFontScale?: number };
/**
 * "Fit back": while a text is shown larger than the default (`scale` > 1) and is limited to lines — its own `numberOfLines`, or `fit`
 * (true = one line, a number = that many) — it may shrink to fit them, at most back to the size it has at the default: its own floor
 * (`minimumFontScale`, 1 when it has none) divided by the scale. So it never needs more room than it has today. Null = add nothing:
 * at the default size, below it, and for a text with no limit (which wraps and grows).
 */
export function fitProps(scale: number, given: Fit, fit?: boolean | number): Fit | null {
  const lines = given.numberOfLines || (fit === true ? 1 : typeof fit === "number" ? fit : 0);
  if (!(scale > 1) || !lines) return null;
  return { numberOfLines: lines, adjustsFontSizeToFit: true, minimumFontScale: (given.minimumFontScale ?? 1) / scale };
}

/**
 * iOS's large-content viewer for a control whose text is capped: at an accessibility text size, touch and hold shows `title` large in
 * the middle of the screen. Spread it on the control's pressable. React Native has a prop for the title and none for the picture.
 */
export const largeContent = (title: string) => ({ accessibilityShowsLargeContentViewer: true, accessibilityLargeContentTitle: title }) as const;

/**
 * THE text of the app: the only place React Native's `Text` is drawn (textScale.guard.test.ts). It follows the phone's text size up
 * to the cap of the family it is drawn in. A span inside another text is a `KitText` with its parent's `scale`: React Native lets
 * every text, nested or not, scale by itself.

export function KitText({ scale = "chrome", fit, ...rest }: KitTextProps) {
  if (scale === "fixed") return <Text {...rest} allowFontScaling={false} />;

}
/** A line-limited text: the only kind that listens for the phone's text size, to fit back while it is shown larger than the default. */

  const cap = textCap(useTone(), how);
